# 需求变更

## Trigger
范围、业务规则、接口或验收条件发生变化。

## Input
变更来源、当前 brief / prd / decisions、变更前版本。

## Required Context
受影响的 analysis、design、任务和知识引用；[PRD](../../standards/prd.md)、[验证](../../standards/validation.md)。

## Steps
1. 记录变更原因、提出人、目标及确认状态。
2. 分析范围、流程、数据、API、兼容、排期和验收影响。
3. 将待确认方案记录为 Proposed，确认后更新有效决策及受影响产物。
4. 在 changelog 记录前后变化与来源；标记需重做的评审和任务。
5. 对变化及其关联流程复验。

## Output
更新后的需求产物、变更记录、决策和复验结果。

## Validation
范围、设计、字段和验收条件一致；被替代决策可追溯；未确认项具有明确状态。

## Persistence
执行公共会话结束协议，同步需求与项目索引。
