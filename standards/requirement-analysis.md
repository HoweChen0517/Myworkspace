# 需求分析标准

先明确问题与证据、目标、范围、角色、触发、现有流程、约束和依赖，随后分析目标流程、系统边界、状态变化、规则、数据来源、权限、异常及兼容性。

事实记录来源路径或批准的链接、定位和日期；假设记录验证动作；未知项标记 Unknown。来源冲突时保留各方证据与待确认问题。

复杂度按系统数量、规则耦合、依赖和风险判断：SIMPLE 适合单点调整；STANDARD 适合独立功能或接口协作；COMPLEX 适合跨系统、多模块和长期演进。记录选择依据，范围变化时重新评估。

分析产物应能解释目标方案解决的问题、受影响对象、关键依赖与验收方式。重要选择在 decisions 中记录替代方案与理由。
